# AAE Documentation Consistency Matrix

This matrix records the consistency analysis between the authoritative AAE documentation sources across key engineering domains.

| Area | Authoritative Source | Requirement / Architectural Baseline | Implementation Implication | Conflict Identified | Resolution / Status |
|---|---|---|---|---|---|
| **Provider** | `N8N_CAPABILITY_MAP.md` | Provider abstraction layer; truthful classification of endpoints. | n8n operations mapped to verified endpoints. Unverified features marked `UNKNOWN` or `UNSUPPORTED`. | `docs/N8N_CAPABILITY_MAP.md` was empty (0 bytes). | Reconciled with verified content from `SKILLS/N8N_CAPABILITY_MAP (1).md` (ADR 0001). |
| **Execution** | `N8N_CONTROL_SURFACE.md` | Abstract `execute_workflow()`; direct `/run` returns 405; webhook is verified workaround. | Adapter must inspect workflow for webhook trigger before executing workaround; fail closed otherwise. | Potential assumption that webhooks are universal. | Resolved per ADR 0002: Native check → Webhook check → Block if incompatible. |
| **OpenAPI** | `N8N_CONTROL_SURFACE.md` & `N8N_CAPABILITY_MAP.md` | `GET /openapi.json` returns Vue editor HTML on n8n 2.38.7. | Do NOT dynamically generate client/adapter from `/openapi.json`. | None. Confirmed by runtime test. | Classified as `KNOWN_LIMITATION` for n8n 2.38.7. |
| **Requirement Translation** | `AAE_REQUIREMENT_TRANSLATION_SPEC.md` | 7-phase requirement translation, confidence scoring (`EXPLICIT`, `INFERRED`, `ASSUMED`, `UNKNOWN`, `CONFLICTING`). | Translate natural language into structured specification before building workflows. | None in Phase 0. Translation engine is Phase 9. | Deferred to Phase 9. Foundation prepared. |
| **Agent State** | `AAE_AGENT_SPECIFICATION.md` | Explicit 17-state finite state machine; zero-trust boundary. | Orchestrator controls state transitions, preventing illegal jumps or autonomous unapproved execution. | None. State machine consistent with Architecture. | Formal domain model to be implemented in Phase 1. |
| **Architecture** | `AAE Architecture.md` | Layered architecture: API → Orchestrator → Provider Tool Layer → Provider Adapter. | Clean separation; core domain never imports n8n-specific models or endpoints. | None. Technology stack aligned (FastAPI, PostgreSQL, Pydantic). | Implemented in Phase 0 provider foundation. |
| **Security** | `AAE Security Policy.md` | Zero-trust agent principle; secret redaction in logs/audit; fail-closed; human-in-the-loop approval. | Custom logging formatter regex-redacting secrets; no secrets in `/health` or `/ready`; typed config masking. | None. Consistent across all documents. | Implemented in Phase 0 security baseline. |
| **Database** | `AAE Architecture.md` & `CODEX_IMPLEMENTATION_PLAN.md` | PostgreSQL required at runtime; Alembic migrations; SQLAlchemy 2.0 ORM. | PostgreSQL is required for runtime; SQLite allowed only in isolated unit tests. | Docker service offline in host dev environment. | Documented in ADR 0003 as external environment limitation. |
| **Skills** | `AAE_AGENT_SKILLS.md` | Specialist skills provide expertise; deterministic controls provide authority. | Skills define reusable instructions for agents; cannot override policy. | None in Phase 0. Skills registry is Phase 21. | Deferred to Phase 21. |
| **Benchmark** | `AAE_EVALUATION_BENCHMARK.md` | Evaluation based on working automation and verifiable outcomes, not generated JSON. | Automated regression and benchmark test suite must verify actual execution. | None in Phase 0. Benchmark is Phase 22. | Deferred to Phase 22. |
| **Implementation Plan** | `CODEX_IMPLEMENTATION_PLAN.md` | Phased implementation: Phase 0 (Bootstrap) through Phase 26. | Strict adherence to Phase 0 scope; no premature AI models or workflow generators. | None. Implementation strictly adheres to Phase 0. | Gate rules enforced. |
